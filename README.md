# 大麦抢票助手

基于 [prelearn-code/damai](https://github.com/prelearn-code/damai)「模式 0」改出来的 **REDMI K80 适配版**：通过 USB 和 adb，在安卓真机上替你在大麦 App 里连续点击「购买 → 确认 → 立即提交」。走到支付宝收银台就停下，**付款永远由你自己完成**。

> ## ⚠️ 先看这里：项目状态
>
> **3 次实战，0 次成功。** 2026-10-14 在一台 REDMI K80 上跑了 3 场热门演唱会，3 场都没抢到。每次都卡在一个新问题上（详见 [已知问题](#已知问题和实战记录)），前两个已修，第三个只做到了能自动保存现场，**还没修**。
>
> 发出来是为了让有兴趣的人接着修。**不要指望拿来直接抢到票。**

> ## ⚖️ 使用前请知悉
>
> - 自动化抢票**可能违反《大麦用户服务协议》**，可能导致账号被风控、限制购票甚至封号。实战中已多次触发大麦安全验证页。
> - 本项目**不包含、也不接受**任何绕过风控、验证码、滑块、设备指纹的代码。遇到风控只会返回一级，然后由你自己处理。
> - 仅供学习 Android UI 自动化，**禁止用于倒卖、黄牛或任何商业用途**。使用后果自负。

## 它是怎么工作的

```text
你手动停在演唱会详情页
        │
开售前 2 秒 ─► 每 0.15 秒点一次屏幕右下角同一个位置
        │      （这个位置同时落在 详情页「购买」/ 票档面板「确认」/ 确认页「立即提交」三个按钮上）
        ▼
进入确认订单页 ─► 停止盲点，改为「看到什么页面才点什么」
        │
        ├─ 看到「立即提交」  → 点一次
        ├─ 看到「继续尝试」  → 读出按钮实际位置，点它的中心（弹窗 1 秒不消失会再点）
        ├─ 看到「库存不足」  → 一下都不点，停止，提示你手动换票档
        ├─ 看到认不出的弹窗 → 一下都不点，自动截图
        ├─ 看到风控验证页   → 只按一次返回键
        └─ 支付宝到前台     → 立即停止，等你自己付款
```

脚本**不会**帮你选场次、票价、观演人，这些必须在开售前在大麦里手动预选好。

## 安全规则（代码里写死的）

| 规则 | 说明 |
| --- | --- |
| 绝不点支付宝付款 | 支付宝一到前台就停止，金额由你核对 |
| 绝不点「返回重新选购」 | 点了等于放弃这单 |
| 只认文字是「继续尝试」的按钮 | 12:20 实战教训：库存不足弹窗的按钮和「继续尝试」是同一个控件 ID |
| 认不出的弹窗不点 | 只截图留证 |
| 风控页只返回一级 | 不自动拖滑块、不绕过验证 |
| 每次点击前确认大麦在前台 | 前台是别的 App 或查不到时一律不点 |
| 屏幕分辨率必须完全一致 | 不一致直接报错退出，因为所有坐标都按分辨率校准 |

## 支持的设备

| 设备 | 状态 |
| --- | --- |

| 其他 1440×3200 的安卓机 | ⚠️ 理论可用，需自己用预检和坐标检查确认 |
| 其他分辨率 | ❌ 需要自己校准坐标，见 [适配其他手机](#适配其他手机) |

电脑端：**Windows 10/11**（bat 和 ps1 脚本是 Windows 的；Python 部分本身跨平台）。



## 第一次使用：从零开始配置

整个过程大约 20 分钟，只需要做一次。

### 第 1 步：安装 Python

1. 打开 <https://www.python.org/downloads/> 下载 **Python 3.11 或更新版本**。
2. 安装时**勾选「Add python.exe to PATH」**。
3. 打开 PowerShell，输入下面的命令，能看到版本号就成功了：
   ```powershell
   python --version
   ```

### 第 2 步：下载本项目

```powershell
git clone https://github.com/ByteSparkX/damai.git
cd damai-ticket-helper
```

没装 git 的话，在 GitHub 页面点绿色的 **Code → Download ZIP**，解压后用 PowerShell 进入那个文件夹。

> 后面所有命令都在这个项目文件夹里执行。

### 第 3 步：安装 Python 依赖

```powershell
python -m venv .venv-phone
.\.venv-phone\Scripts\python.exe -m pip install -r requirements-phone.txt
```

> ⚠️ 虚拟环境的名字**必须是 `.venv-phone`**，bat 脚本是按这个名字找的。
>
> 国内下载慢可以加镜像：`... pip install -r requirements-phone.txt -i https://pypi.tuna.tsinghua.edu.cn/simple`

### 第 4 步：下载 adb（Google 官方 platform-tools）

1. 下载：<https://dl.google.com/android/repository/platform-tools-latest-windows.zip>
2. 解压到**项目文件夹里**，解压后的路径应该是：
   ```text
   damai-ticket-helper\platform-tools\adb.exe
   ```

也可以用命令一步完成：

```powershell
Invoke-WebRequest https://dl.google.com/android/repository/platform-tools-latest-windows.zip -OutFile platform-tools.zip
Expand-Archive platform-tools.zip -DestinationPath . -Force
Remove-Item platform-tools.zip
.\platform-tools\adb.exe version
```

### 第 5 步：手机设置

按顺序做完：

1. **开启开发者选项**：设置 → 我的设备 → 全部参数与信息 → 连续点「OS 版本」7 次。
2. **开启 USB 调试**：设置 → 更多设置 → 开发者选项 → 打开「**USB 调试**」。
3. **开启 USB 调试（安全设置）**：同一页面打开「**USB 调试（安全设置）**」。
   - 小米/红米**必须开**，否则电脑发出的点击会被系统静默拦截：脚本看起来在跑，其实什么都没点中。
   - 需要登录小米账号、插着 SIM 卡。
4. **（建议）充电时屏幕保持唤醒**：开发者选项 → 打开「充电时屏幕保持唤醒」，防止等待开售时息屏。
5. **把屏幕分辨率改成 WQHD+**：设置 → 显示与亮度 → 屏幕分辨率 → 选「**WQHD+**」。
   - K80 默认是 FHD+（1080×2400），**不改的话预检必定 FAIL**。

### 第 6 步：连接电脑

1. 用数据线连接手机和电脑，USB 模式选「**传输文件**」。
2. 手机弹出「允许 USB 调试吗？」时，勾选「**一律允许**」再点确定。
3. 验证：
   ```powershell
   .\platform-tools\adb.exe devices
   ```
   看到一行 `xxxxxxxx    device` 就成功了。如果显示 `unauthorized`，说明手机上还没点允许。

> **多台手机同时连接时**，要告诉脚本用哪一台：
> ```powershell
> $env:DAMAI_DEVICE_SERIAL = "你的序列号"
> ```
> 只连一台时不用设置，脚本会自动识别。

### 第 7 步：跑一次预检

双击项目里的 **`precheck_K80.bat`**，或者执行：

```powershell
.\.venv-phone\Scripts\python.exe tools\precheck_K80.py
```

预检**只读**，不会点你的手机。它会检查 adb、设备连接、机型、分辨率、大麦和支付宝有没有装、前台 App、屏幕常亮、电量、电脑时钟准不准。

最后一行显示 **`0 项 FAIL`** 才能继续。常见 FAIL 怎么处理：

| FAIL 项 | 解决办法 |
| --- | --- |
| ADB：找不到 adb.exe | 第 4 步没做，或者解压位置不对 |
| 设备连接：没有找到唯一一台已授权设备 | 检查数据线；手机上点「允许 USB 调试」；多台设备时设置 `DAMAI_DEVICE_SERIAL` |
| 分辨率：当前生效 1080x2400 | 第 5 步第 5 条，改成 WQHD+ |
| 大麦 App / 支付宝 App：未安装 | 在手机上安装它们 |
| u2 window_size 不一致 | 同上，改分辨率；改完重新插一次数据线 |

### 第 8 步：检查点击位置准不准（强烈建议）

脚本靠一个固定坐标 `(1119, 3088)` 点击按钮，不同手机、不同大麦版本，按钮位置可能不一样。

1. 手机打开**任意一场演出的详情页**，执行：
   ```powershell
   .\.venv-phone\Scripts\python.exe tools\inspect_point_K80.py detail
   ```
   看输出里 `MAIN_ACTION_POINT` 那一段，**最上面一行应该是底部的橙色购买按钮**。
2. 在手机上点开票档面板（选场次和票价的那一层，**不要点确认**），再执行：
   ```powershell
   .\.venv-phone\Scripts\python.exe tools\inspect_point_K80.py sku
   ```
   这次应该命中 `btn_buy_view`（底部的确认 / 提交按钮）。

两个都命中了，配置就完成了。

## 每次抢票的操作流程

### 开售前一天或更早

- [ ] 在大麦里**设置好实名观演人**（演出详情页上的「预选本次实名抢票观演人 → 去设置」）。
- [ ] 点「预约抢票」，**选好场次和票价**，提交预约。详情页显示「已设置本次抢票信息 → 已完成」才算好。
  - 建议**多选几个票档**：实战中单一票档几十秒就卖光了。
- [ ] 支付宝里余额或银行卡够用。

### 开售前 10 分钟

1. 手机插上数据线，打开大麦，**停在目标演出的详情页**（底部是「预约抢票 / 立即购买」橙色按钮的那一页）。
   - 不要停在票档面板上，也不要停在确认页上。
2. 手机开勿扰模式，关掉闹钟、悬浮窗和后台的其他 App。
3. 双击 `precheck_K80.bat`，确认 **0 项 FAIL**。

### 开售前 2–5 分钟，启动脚本

**方式 A：双击（推荐）**

双击 **`grab_K80.bat`**，按提示输入开售时间：

```text
2026-10-20 12:00:00
```

它会先自动跑一遍预检（有 FAIL 就不启动），然后开始等待，开售前 2 秒开始点击。

**方式 B：命令行**

```powershell
.\.venv-phone\Scripts\python.exe scripts\damai_mode0_K80.py "2026-10-20 12:00:00"
```

**方式 C：定时启动（你不在电脑前时）**

```powershell
powershell -ExecutionPolicy Bypass -File tools\launch_at.ps1 `
  -LaunchAt "2026-10-20 11:58:00" -SaleTime "2026-10-20 12:00:00" -Tag 1200
```

到 `LaunchAt` 时间自动预检，通过后启动抢票脚本，全程每 2 秒记录手机当前页面，结束后导出手机系统日志。所有记录在 `artifacts\launch_1200.log`。

> ⏰ 时间格式必须是 `YYYY-MM-DD HH:MM:SS`，按**电脑的本地时间**算。预检会检查电脑时钟和阿里云时间差多少，超过 200ms 会提示你同步 Windows 时间。

### 开售时

- **别碰手机**，让脚本跑。
- 但**请盯着屏幕**，遇到下面的情况马上手动接手：
  - 页面卡在同一个地方好几秒没动；
  - 弹出滑块或验证码（脚本不处理）；
  - 脚本提示库存不足后停止了（这时去手动换票档）。
- 想中途停掉脚本：关掉 bat 窗口，或在 PowerShell 里执行 `Get-Process python | Stop-Process`。

### 跳到支付宝之后

脚本会自动停止。**自己核对演出、场次、票价、张数、观演人和金额**，确认没问题再付款。

不想买的话直接退出支付宝即可，订单超时会自动取消。

## 看懂运行结果

脚本结束时会输出一段 JSON，用 `grab_K80.bat` 运行的话也会保存在 `artifacts\result_时间.json`。最重要的是 **`status`** 字段：

| `status` | 意思 | 你该做什么 |
| --- | --- | --- |
| `alipay_reached` | ✅ 已经到支付宝收银台 | 赶紧核对后付款 |
| `terminal_no_retry_option` | 遇到「库存不足 / 返回重新选购」，脚本停了 | 你选的票档卖完了，手动换票档或等回流票 |
| `timeout` | 开售后 10 分钟都没成功 | 看下面的现场文件找原因，然后提 Issue |
| `timeout_before_start` | 启动时开售时间已经过去太久，一下都没点 | 检查输入的时间对不对 |
| `error` | 程序出错 | 看 `worker_error` 字段 |

其他有用的字段：

| 字段 | 含义 |
| --- | --- |
| `main_tap_count` / `retry_tap_count` | 盲点次数 / 点「继续尝试」的次数 |
| `retry_repeat_count` | 「继续尝试」弹窗没消失、额外补点的次数 |
| `skipped_retry_count` | 想点「继续尝试」但没拿到可靠的按钮位置、所以没点的次数 |
| `sold_out_dialog_seen` | 有没有见到库存不足弹窗 |
| `unknown_dialog_hits` | 见到认不出的弹窗的次数 |
| `risk_verification_hits` | 进入风控验证页的次数（**这个数大于 0 就要小心账号了**） |
| `first_tap_wall_time` | 第一次点击的时间（毫秒） |
| `dialog_snapshots` | 自动保存的现场文件路径 |

JSON 前面每一行是过程日志：

- `state_probe`：页面或状态变了；
- `heartbeat`：页面没变化，每秒报一次当前页面和停留了几秒；
- `dialog_text`：遇到库存不足或认不出的弹窗时，弹窗上的文字；
- `dialog_snapshot` / `stuck_page_snapshot`：自动保存的现场，附带屏幕底部按钮的文字和状态。

### 自动保存的现场文件

都在 `artifacts\` 文件夹里，什么时候会保存：

| 文件名 | 什么时候保存 |
| --- | --- |
| `stuck_retry_dialog_*.png/.xml` | 「继续尝试」弹窗超过 1 秒没消失 |
| `stuck_sold_out_dialog_*` | 出现库存不足弹窗 |
| `stuck_unknown_dialog_*` | 出现认不出的弹窗 |
| `stuck_order_page_loading_*` 等 | 开售后在同一个非弹窗页面卡住超过 3 秒 |

`.png` 是截图，`.xml` 是界面结构（每个控件的文字、ID、位置、能不能点）。每类最多存 3 份，不会拖慢抢票。

> 🔒 **这些文件里有你的手机号、观演人姓名、订单信息。** 发到 Issue 之前一定要打码或删掉敏感内容，`.gitignore` 已经把整个 `artifacts\` 排除了。

## 适配其他手机

可调的常量都在 `scripts/damai_mode0_K80.py` 顶部：

| 常量 | 默认值 | 含义 |
| --- | --- | --- |
| `DEVICE_SERIAL` | `""` | 留空自动识别；也可以用环境变量 `DAMAI_DEVICE_SERIAL` |
| `EXPECTED_SCREEN_SIZE` | `(1440, 3200)` | 必须和手机实际分辨率完全一致 |
| `MAIN_ACTION_POINT` | `(1119, 3088)` | 盲点坐标，要同时落在详情页购买按钮、票档面板确认按钮、确认页「立即提交」上 |
| `PRECLICK_LEAD_S` | `2.0` | 开售前几秒开始点 |
| `CLICK_INTERVAL_S` | `0.150` | 盲点间隔（秒） |
| `MAX_RUNTIME_AFTER_SALE_S` | `600` | 开售后最多跑多久 |
| `RETRY_REPEAT_AFTER_S` | `1.0` | 「继续尝试」弹窗不消失时，多久补点一次 |
| `SOLD_OUT_CONFIRM_COUNT` | `2` | 连续几次识别到库存不足才停止 |
| `STUCK_PAGE_SNAPSHOT_AFTER_S` | `3.0` | 非弹窗页面卡住多久开始保存现场 |

**校准一台新手机：**

1. 查分辨率：`.\platform-tools\adb.exe shell wm size`，把结果填进 `EXPECTED_SCREEN_SIZE`（有 `Override size` 时以它为准）。
2. 分别停在**详情页**和**票档面板**，各跑一次 `tools\inspect_point_K80.py`，从输出里找到底部购买按钮和确认按钮的 `bounds`。
3. 取**两个按钮范围重叠部分**里的一个点，填进 `MAIN_ACTION_POINT`。坐标离按钮边缘最好留 30 像素以上。
4. 确认页的「立即提交」要等开售后才能验证，第一次实战请盯紧。
5. 「继续尝试」的位置**不用校准**，脚本会实时读按钮的位置。

> 改坐标时**不要删掉分辨率校验**，它是防止点错位置的最后一道保险。

### 🔴 问题 1（最需要修）：确认页检测不到「立即提交」按钮

- **现象**：进入 `DmOrderActivity` 后，脚本一直看到 `order_activity_title`（判断为 `order_page_loading`），始终找不到「文字等于 `立即提交` 且可点击」的控件，于是一直等。
- **日志线索**：大麦在 13:00:03、05、07 连续弹出 Toast，手机日志里 `DMToastUtil` 打印 `TYPE_CONTINUE_`，可能是提交被拦下后的「继续」类提示。
- **猜测原因**（没有证据，需要现场验证）：
  1. 按钮在提交被拦下后一直处于 `clickable=false` 或 `enabled=false`；
  2. 按钮文字变了，比如「提交中」「排队中」或带了倒计时，精确匹配不上；
  3. 盲点阶段结束得太早：13:00:03.25 的最后一次盲点，落在确认页刚打开、按钮还没渲染的时候。
- **怎么帮忙**：现在卡住超过 3 秒会自动保存 `stuck_order_page_loading_*.xml/.png`，日志的 `bottom_controls` 里会列出屏幕底部所有控件的文字和可点状态。拿到一份现场，基本就能确定原因。
- **相关代码**：`FastPageProbe.read()`、`Mode0StateController.observe()` 里 `PAGE_ORDER_LOADING` 的分支、`damai_android_tail.run_tail_probe_loop()`。

### 🟡 问题 2：风控页判断会误报

原作者用 `cn.damai:id/water_mark_view_id` 判断风控验证页，但这个控件在正常的**详情页和票档面板上也有**（全屏水印）。目前只在已提交订单之后才检查，所以影响不大；但如果要扩大检测范围，必须换一种判断方法。

### 🟡 问题 3：抢不到的根本原因是票少

3 场都在开售后 2–3 秒进入了确认页，比手动快不了多少。热门票档几十秒就卖光，脚本只能做到更快提交、卖完时及时停下，**不能保证抢到**。

### 🟡 问题 4：只在一台手机上验证过

坐标、页面结构、控件 ID 都基于 REDMI K80 + 大麦 9.0.35。大麦一更新，这些都可能失效。
